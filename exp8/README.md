# exp8 — синергія simargl + gamayun + svitovyd

**Питання.** Чи доповнюють одне одного три пошуки пантеону, і в яких пропорціях брати
їхні результати? Концепт і план — `concepts/GAMAYUN.md`, розділ 13.

**Дані.** Ті самі 200 тестових і 200 dev-задач, що й в exp7 (правило `modn` з exp3).
Для кожної задачі будуються три ранжовані списки файлів:

| Джерело | Як отримано | Витік тестових задач |
|---|---|---|
| **gamayun** | наївний Байєс на онтології exp7, побудованій без тестових (і dev) задач; параметри підібрано на dev | немає |
| **simargl** | індекс задач користувача (`<repo>/.simargl`, bge-small, усі задачі). Тестові й dev-задачі **викидаються з результатів**, файли збираються з решти 20 найближчих задач, як у `_search_task` | немає (відфільтровано) |
| **svitovyd** | карта користувача (`<repo>/.svitovyd/map.txt`, код на HEAD). Ідентифікатори, прямо названі в тексті задачі, дають бал файлам, що їх визначають (вага idf). Готового «текст → файли» у svitovyd немає, це ранжування зібране з його карти в exp8 | код з майбутнього відносно задач (див. застереження) |

Поєднання (параметри підібрано на dev, тест один раз):
- **зважений RRF:** score(f) = Σ w_s / (60 + rank_s(f)), ваги з {0, 0.5, 1, 2};
- **квоти:** скільки з 10 позицій віддати кожному джерелу; всередині десятки порядок за RRF.

```
python synergy.py --project sonar      # ~3 хв (CPU)
python synergy.py --project flink
```

## Результати (тест; метрики файлів, топ-10)

| | sonar MAP | sonar hit@10 | flink MAP | flink hit@10 |
|---|---|---|---|---|
| gamayun | 0.116 | 0.44 | 0.124 | 0.55 |
| simargl (bge-small, задачі) | 0.132 | 0.44 | 0.142 | 0.47 |
| svitovyd (карта HEAD) | 0.004 | 0.04 | 0.038 | 0.17 |
| **RRF, ваги з dev** | **0.149** | 0.47 | 0.156 | **0.58** |
| RRF, рівні ваги | 0.147 | **0.53** | 0.156 | **0.58** |
| **квоти з dev** | 0.148 | 0.49 | **0.165** | **0.58** |

Підібрані на dev параметри:

| | sonar | flink |
|---|---|---|
| ваги RRF (g / s / v) | 0.5 / 2 / 0 | 0.5 / 0.5 / 0.5 |
| квоти з 10 (g / s / v) | 1 / 9 / 0 | 6 / 4 / 0 |

**Хто знаходить правильні файли** (правильні файли в топ-10 хоча б одного джерела):

| | sonar | flink |
|---|---|---|
| лише simargl | 38 % | 28 % |
| лише gamayun | 31 % | 30 % |
| gamayun і simargl | 27 % | 28 % |
| лише svitovyd | 3 % | 7 % |
| інші комбінації | 1 % | 6 % |

**Стеля: чи є правильний файл хоч десь в об'єднанні** (тест):

| | sonar hit | sonar recall | flink hit | flink recall |
|---|---|---|---|---|
| top-5 кожного (≤ 15 кандидатів) | 0.50 | 0.21 | 0.61 | 0.27 |
| top-10 кожного (≤ 30) | 0.61 | 0.27 | 0.68 | 0.32 |
| top-50 кожного (≤ 150) | 0.76 | 0.41 | 0.79 | 0.48 |

## Висновки

1. **Синергія справжня.** gamayun і simargl спільно знаходять лише 27–28 % правильних файлів;
   кожен із них приблизно третину правильних файлів знаходить **сам**. Поєднання дає +13 % MAP на sonar
   (0.149 проти 0.132) і +16 % на flink (0.165 проти 0.142) відносно кращого окремого джерела.
2. **Пропорції залежать від проєкту.** На sonar dev майже все віддає simargl (квоти 1 / 9), на flink —
   gamayun (6 / 4). Перенести одну пропорцію на всі проєкти не можна. **RRF з рівними вагами** —
   стійкий варіант за замовчуванням: на обох проєктах він на рівні підібраного (0.147 / 0.156).
3. **90 % hit на файлах із цими кандидатами недосяжні.** Навіть ідеальний перерангувальник
   (Jev, LLM) над об'єднанням top-5 трьох джерел дасть щонайбільше hit 0.50 / 0.61, а над об'єднанням
   top-50 — 0.76 / 0.79. Щоб наблизитись до 90 %, спершу треба розширювати кандидатів: файловий
   індекс simargl, сусіди за `co_changes_with`, папки. Перерангування має сенс після цього.
4. **svitovyd тут оцінено несправедливо.** Його карта — код 2026 року, а задачі — 2010–2024.
   У поточному коді існують лише 20 % (sonar) і 40 % (flink) правильних файлів тестових задач.
   Лише 39 зі 200 задач sonar мають хоч один такий файл. До того ж у карті sonar немає файлів
   TypeScript (`sonar-web`). На flink, де розбіжність менша, svitovyd уже дає 7 % унікальних
   знахідок. Для свіжих задач його внесок має бути більшим.

## Застереження

- simargl — bge-small на CPU. В exp3 найкращим був bge-large, з ним simargl, імовірно, сильніший.
- simargl вбудовував `DESCRIPTION` у форматі ADF (розмітка Jira); запити — очищений текст.
- Відфільтровані тестові задачі все одно лежать в індексі simargl, але в результати не потрапляють.
  Звичайні навчальні задачі залишаються, як і в gamayun.
- Ранжування svitovyd зібране в exp8 з його карти, а не є його вбудованою функцією.
