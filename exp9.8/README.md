# exp9.8 — глибокі задачі: Haiku з пошуком у коді (G) проти Haiku з індексами (P)

**Питання.** На задачах, де голка лежить глибше за слова задачі (exp9.7), чи дають індекси пантеону те,
чого не дає grep?

**Сетап.**
- п'ять задач exp9.7 як **D1–D5**; для кожної checkout на коміті до розв'язку і карта svitovyd (`prep8.py`);
- **група G** — `grep` + `read`;
- **група P** — `compass`, `gamayun`, `show`, `simargl`, `find`/`defines`/`trace` (svitovyd), `companions` +
  `read`, **без grep** (`lab8.py`);
- онтологія exp7 без відкладених задач, simargl вирізає dev і test — витоку немає;
- **промпти однакові** (`make_prompts.py` будує обидва з одного шаблону): відрізняються лише буквою групи
  і списком команд, без підказок щодо стратегії (на відміну від exp9.6). Бюджет ~15 викликів на задачу,
  відповідь — 10 файлів;
- по одному агенту Haiku на групу, усі п'ять задач.

```
python prep8.py           # checkout + карти svitovyd, tasks.md, ids.json (~7 хв)
python make_prompts.py    # prompt_G.md, prompt_P.md
python score.py           # out/answers_G.json, out/answers_P.json -> out/score.md
```

## Висновки

1. **Голки, до яких веде лише зв'язок «змінюються разом», знайшли тільки індекси:** у D4 (`TelemetryDaemonTest`) і
   D5 (`plugins/sonar-core-plugin/pom.xml`) P їх знайшла, G — ні: за словами задачі туди не дійти. У D2 голку
   знайшли обидві, бо `TagsAction` прямо названо в тексті через `api/issues/tags`. Це перший прямий доказ тези:
   **коли голка лежить глибше за слова, зв'язки онтології знаходять те, чого не знаходить grep.**
2. **P не гірша ні в чому і дешевша:** менше викликів, майже вдвічі менше виводу. Індекси замінили grep-перебір,
   а не додались до нього.
3. **Без підказки в промпті Haiku сама перейшла на зв'язки:** найчастіші команди P — simargl, find, companions;
   у звіті агент назвав `companions` найнадійнішим сигналом, а simargl — найсильнішим входом.
4. **D1 провалили обидві групи.** Правильні файли — бекенд (`WebService.java`, `Changelog.java`, `ListAction.java`):
   P пішла за схожою задачею simargl про фронтенд-сторінку web-api, G — за словом «changelog» у changelog профілів
   якості, хоча `grep changelog` у `sonar-plugin-api` знаходить `Changelog.java` з першого запиту.

## Обмеження

- **5 задач, по одному прогону на групу.** Різниця MAP 0.04 — у межах шуму. «3 голки проти 1» — сильніший сигнал,
  але теж на малій вибірці.
- **Абсолютні числа низькі в обох** (recall 0.25–0.30): глибокі задачі важкі й для Haiku з усім арсеналом.
- **D3:** 12 з 19 правильних файлів створює сама задача, знайти їх у checkout до розв'язку неможливо;
  стовпець «recall файлів, що існували до задачі» це враховує.
- Задачі відібрано за наявністю ланцюжка в онтології (exp9.7), тож вибірка зміщена на користь P так само, як
  вибірка exp9.1 зміщена на користь grep. Наступний крок — більше глибоких задач, у тому числі з flink.
