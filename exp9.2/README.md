# exp9.2 — малі локальні моделі (4k контексту, CPU): пантеон проти пошуку в коді

**Питання.** Чи користуються малі моделі (1–9b) пошуковиками пантеону, коли ті є серед інструментів?
Теза: мала модель не знає, що шукати, тож індекси, що підказують зв'язки, мають замінити їй намір.

**Сетап** (`agent.py`, власний харнес у стилі 1bcoder):
- ті самі 10 задач і checkout'и, що в exp9.1;
- один рядок `ACTION: <команда>` за хід, вікно 4096 токенів (старі ходи випадають), не більше 14 ходів;
- **група A:** `gamayun`, `simargl`, `defines` + `find`, `read`, `keep`, `done`;
- **група B:** `find`, `read`, `keep`, `done` (те, що має 1bcoder);
- супервізор тримає список `keep` (до 10 файлів); після пошуку окремий виклик просить модель упорядкувати
  збережені файли (перемішані, щоб уникнути позиційного зсуву);
- Ollama на panteon, CPU, temperature 0.

```
python agent.py --models tev1:4b --groups A B --tasks T01 T05
powershell -File ladder.ps1                          # драбина моделей, готові епізоди пропускаються
python score.py <truth_9.1.json>                     # -> out/score.json
```

## Висновки

1. **Малі моделі не кличуть індекси, навіть коли ті є:** tev1:4b і gemma4:e2b у групі A жодного разу не
   покликали gamayun; gemma3:1b кликала його з бредом із прикладу промпту. A від B фактично не відрізняється.
   Щоб скористатися індексом, модель мусить мати намір, а саме його їй і бракує, тож теза так не перевіряється.
2. **Малі моделі майже не роблять `keep`:** у 50 з 56 епізодів список порожній.
3. **На складних задачах — нуль у всіх, крім qwen3:4b,** тоді як gamayun без моделі дає там 0.487.
4. Звідси exp9.3: індекси запускаються **до** першого ходу моделі (пасивний старт).
