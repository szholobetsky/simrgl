# exp9.5 — `gamayun compass` на задачах, яких правило не бачило

**Питання.** Компас без LLM — «рідкісний буквальний якір задачі → `git grep`, інакше перший файл
онтології» — дав P@1 0.70 на T01–T10. Але правило складалось на цих самих задачах. Скільки він дає
на задачах, яких не бачив, і чи чесна його впевненість?

**Сетап** (`compass_eval.py`):
- для кожної задачі код на коміті до розв'язку: `git grep` по ревізії `<перший коміт>^`, без checkout;
- онтологія exp7 без dev- і тестових задач, параметри exp9. Параметри підібрано на dev, тож гілка
  онтології на dev трохи оптимістична; гілку якоря і правило впевненості на dev не налаштовували;
- **впевненість задана правилом до оцінки:**
  - висока — якір у 1–3 файлах;
  - середня — якір у 4–30 файлах або докази онтології з двох слів задачі;
  - низька — решта;
- поруч рахується «онтологія сама» (`gamayun search`) на тих самих задачах.

```
python compass_eval.py dev | test | t10     # -> out/<set>.jsonl
python score.py                             # -> out/score.md
```

Сама команда — `gamayun compass "<текст>" --project P [--repo R] [--rev REV]` (`gamayun/compass.py`), а в UI
gamayun — блок Compass на вкладці Search.

## Висновки

1. **0.70 на T01–T10 — переоцінка.** На нових задачах P@1 компаса 0.24–0.28: T01–T10 нетипово «зручні»,
   з кодовими назвами в тексті.
2. **Якір не дає стабільного виграшу:** на test компас кращий за онтологію (+0.04 P@1, +0.08 hit@5), на dev
   трохи гірший. Там, де якір спрацював, `git grep` звужує область правильно, але перший його файл обирається
   погано (сортування «основний код, коротший шлях»). Наступний крок — упорядковувати файли якоря онтологією,
   налаштувати це на dev і перевірити на test один раз.
3. **«Низька» впевненість чесна** — P@1 0 на обох наборах: коли компас каже «не знаю», він справді не знає.
   **«Висока» від «середньої» на test не відрізняється**, тож обіцянки «точно» вона не тримає.
